# UX-1 Everyday Feel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Browsing feels continuous: Back *and* Forward work from the keyboard, the Go menu and ⌘K; relaunch puts the user back in the same view, selection and scroll position; failed thumbnails stop looking like they are still loading; the viewer never shows an empty "Loading media…" box; long jobs (export, XMP import) leave the UI thread; first run offers three paths and a list of recent libraries.

**Architecture:** Most of UX-1 is already in the tree. This plan fills the gaps on top of the existing pieces: the Back trail (`NavigationHistory`), the one-shot startup restore (`pending_restore` / `apply_restored_session`), the motion module (`motion.rs`, with the system Reduce Motion setting), the skeleton cards, the actionable empty states, the toast system, and the welcome and first-scan screens. No schema change. Two `AppConfig` fields are added (`last_scroll_anchor_id`, `recent_libraries`), both `#[serde(default)]`.

**Tech Stack:** Rust 2021, GPUI Kit 0.9 (`gpui-pre` 0.3.11), rfd 0.15, `image` 0.25 (already a dependency, used only for the optional sample library). No new crates.

## Global Constraints

- No SQLite schema change, so no `SCHEMA_VERSION` bump. New persisted state goes in `AppConfig` (`crates/lumina-ui-gpui/src/config.rs`) with `#[serde(default)]`, so an old config file still loads.
- No file or catalog IO on the UI thread. Export, XMP import and sample generation run on `cx.background_executor()`.
- No flat `LuminaApp` fields. New state goes in small structs: `NavigationHistory` (exists), `recent_libraries` (a `Vec<PathBuf>` in `AppConfig`, logic in `app/recents.rs`), `thumb_failures` (a field on `GridState`), `WelcomeState`, `ForegroundJobs`.
- **Shortcut ownership: this plan owns ⌘[ (Back) and ⌘] (Forward)**, as in Safari, Finder and Photos. Plan 4 (`2026-11-05-v1-04-metadata-and-edits.md`, Task "rotate", open question 4) proposed ⌘[/⌘] for Rotate Left/Right; it must pick other keys (Photos uses ⌘R / ⌥⌘R, but ⌘R is Rescan here). The viewer's plain `[`/`]` stay previous/next item.
- **What a history entry is.** A destination = sidebar selection (album, system album, tag, Untagged, Duplicates, Trash) + search query + year + viewer open/closed (`NavigationSnapshot::same_destination`). Selection moves (arrows, clicks) are not entries; they update the current entry's remembered selection. A search typed into the field is not recorded per keystroke: `sync_pending` materialises the live query as one entry when Back/Forward runs or the next explicit change is recorded. Library switch and the startup restore reset the trail (no Back or Forward across libraries). A Back/Forward target whose album or tag was deleted falls back to All Photos (`resolve_navigation_selection`), and a target whose item is gone opens no viewer (`navigation.rs:283-289`). The cap stays 50 entries.
- **Every library switch goes through `open_library`** (recents, palette rows, sample library, new library), never `open_library_inner`, so a running download asks first (`ask_before_leaving`) and the startup restore is dropped. A running import is abandoned on switch (existing `abandon_import` in `open_library_inner`: stops after the current file, copies so far stay); see open question 5.
- **A permanently failed thumbnail** (decode returned `None` or the frame could not be converted) shows a failed card, not the skeleton, until the file is re-upserted or the library is rescanned. The viewer shows a failed stage for the same item. Both say so in text, not only in a tooltip (AGENTS §11).
- Module size: `app/navigation.rs` (1624 lines) and `app/library.rs` (1546 lines) are already far past ~500 lines. New code goes in new modules (`app/history.rs`, `app/recents.rs`). Nothing new is added to those two files beyond call sites.
- User strings go through `i18n.rs` keys (`command.back`, `command.forward`, `command.open_recent`, `command.clear_recents`, `welcome.*`, `grid.no_preview`, `grid.preview_failed`, `viewer.preview_failed`, `viewer.open_default_hint`). UI copy never names tools (memory rule).
- Tests: `#[core::prelude::v1::test]` in `gpui::*` modules. Tests never write config (`save_config` already returns early under `cfg(test)`). Temp dirs only.
- Removing a library from recents never deletes its catalog (`<data_dir>/lumina/catalog_<hash>.db`) or any file.
- debug_selectors (new): `welcome-open-btn` (renamed from `pick-folder-btn`, see Decisions), `welcome-import-new-btn`, `welcome-sample-btn`, `welcome-recent-{i}`, `welcome-recent-remove-{i}`, `welcome-missing-library`, `media-card-failed-{id}`, `viewer-stage-placeholder`, `viewer-stage-failed`. New clickable controls also get an `id`, a `.role(...)` and a label (AGENTS §11), without claiming VoiceOver support.
- New test files are registered in `src/tests/mod.rs` (`mod history; mod session_restore; mod thumbnails;`). Unchanged: `media-card-skeleton-{id}`, `empty-state`, `empty-primary`, `empty-secondary`, `first-scan*`.

## Review Focus

1. **Restore race.** The user clicks an album, types a search or selects a card while the startup scan is still running, and the late restore then moves them somewhere else and wipes their Back trail (`apply_restored_session` calls `reset_navigation_history`). Typed search does not go through `record_navigation_change` (it edits `search_query` via `text_input.rs` `text_edited`), so the guard must sit in `apply_restored_session`, not in the record path. Tests: Task 2 `user_navigation_before_scan_complete_cancels_restore`, `typing_a_search_before_scan_complete_cancels_restore`. Both fail on main today.
2. **Forward truncation.** After Back, a new destination must drop the Forward entries, and Forward must never reopen a viewer for an item that is gone. Tests: Task 1 `new_destination_truncates_forward` and `forward_to_deleted_item_opens_no_viewer`.
3. **⌘] versus the viewer's `]`.** With the viewer open, ⌘] must go Forward and must not step to the next photo. Test: Task 1 `cmd_bracket_in_viewer_navigates_history_not_items`.
4. **Failed thumbnails in tests.** Seed fixtures (`b"test-jpeg-content"`) fail to decode, so once Task 3 lands they show the failed state instead of the skeleton after the decode pool answers. Decodes run on the engine's own thread pool, not the GPUI executor, so `run_until_parked` does not wait for them: tests drive the failure path directly (call the failure handler) and count requests with a `cfg(test)` counter, never by racing `in_flight`. Only two existing assertions use `media-card-skeleton-*` (`tests/ui_automation.rs:444-452` and `:565`), both on the first draw; `debug_bounds` is cumulative, so they keep passing, but check them. Test: Task 3 `failed_decode_is_marked_once_and_not_rerequested`.
5. **Removing from recents is not deleting.** Test: Task 6 `remove_recent_keeps_catalog_and_folder`.
6. **Export off the UI thread.** A frame must not wait on export IO, and a second export started while one runs must be refused, not queued. A job that finishes after a library switch must not refresh the new library. Tests: Task 4 `export_runs_in_background_and_refuses_a_second`, `xmp_result_after_library_switch_does_not_refresh_the_new_library`.
7. **Invisible modals on the welcome screen.** Preferences, About and the shortcut sheet render only on the library root. Registering their actions on the welcome root without rendering them would set `preferences_open` invisibly, and the modal key handler would then swallow every key on the welcome screen. The keyboard already does this today (⌘K, ⌘/, ⌘, fall through the welcome block). Tests: Task 7a `welcome_cmd_k_does_not_open_an_invisible_palette` (fails on main) and, if Preferences is registered there, `welcome_preferences_paint_and_escape_closes`.

## Decisions

1. **Forward reuses `NavigationHistory`.** Add `go_forward` plus `can_go_back`/`can_go_forward`, and move the type to `app/history.rs`. *Rejected:* a second "forward stack". The cursor model already keeps those entries, so a second stack would duplicate the truncation logic.
2. **Keyboard: ⌘[ and ⌘], handled in `handle_key_down` before the viewer's key handling.** *Rejected:* adding GPUI `KeyBinding`s. No other shortcut uses them, and mixing the two dispatch paths risks double handling. The cost is that native menu items show no shortcut glyph. The Go menu titles carry no glyph either. The sheet and the palette show it.
3. **A Go menu (Back, Forward) and palette commands, no toolbar buttons.** The design explicitly has none (`toolbar.rs:138`). Whether to add them is listed under open questions.
4. **Scroll restore anchors on the first visible item's id, not on a row number.** Columns change with window size, and new photos shift indices in a date-sorted view. On restore, `find_active_index(anchor)` (chunk walk at restore only, `library.rs:1071`) → `scroll_to_item_strict(row, Top)`. Because GPUI keeps only one deferred scroll, the selection reveal runs only when the anchor is missing or the selected row would fall outside the anchored viewport (`anchor_row..anchor_row + visible_rows`, with `visible_rows` from `base_handle.bounds()` / `row_height()`); otherwise it would overwrite the anchor scroll. The anchor is written by every `save_config` (debounced session save, window-bounds save, quit); scrolling itself does not schedule a save (no per-scroll IO). *Rejected:* a pixel offset, which breaks on any column or density change.
5. **Keep restoring on `ScanComplete`, and drop it if the user acted first.** The guard is one check at the top of `apply_restored_session`: if `self.navigation_snapshot() != NavigationSnapshot::default()` (the state `open_library_inner` left), the user has moved (album, search typed or set, year, tag rename, card selection, viewer); drop `pending_restore`, keep their trail, and call `save_config` so their state becomes the session. One guard covers every path, including the typed search that never reaches `record_navigation_change`. *Rejected:* cancelling inside `record_navigation_change` (misses typed search and `tags.rs` assignments, and needs `cx` threaded through 6 call sites). *Rejected:* restoring right after open. During the scan `BatchDiscovered` shifts indices, and position-based selection would go stale (AGENTS §5.3). Known limit: if the user acts during the scan and quits before `ScanComplete`, the old session stays on disk (saves wait for the restore, `state.rs:648`).
6. **The viewer is not reopened on relaunch.** Launching into a fullscreen viewer, possibly with video, is surprising, and Photos does not do it. The selection is restored and Enter opens it.
7. **Failed thumbnails: a per-library `Arc<Mutex<HashSet<MediaId>>>` on `GridState`, filled by the decode callback (it captures that library's `Arc`, so a late failure from a closed library cannot mark an id in the new one), cleared for an id when the file is re-upserted (`BatchDiscovered`) or removed, and wholesale on Rescan.** The callback also sends `UiMessage::ThumbnailFailed(id)`, whose handler only calls `cx.notify()`, so the failed card paints without waiting for an unrelated redraw. The viewer reads the same set. A failure includes an offline file (unmounted volume); Rescan (⌘R, which now calls `rescan_library`) is the retry, and Reveal in Finder (⇧⌘R, context menu) stays available. *Rejected:* a disk negative cache in core. That is a schema- or cache-format change for an edge case, and in-memory state gives the same UX. *Rejected:* a per-card Retry button: one undecodable file decodes the same way twice, and Rescan already retries all.
8. **Viewer motion: fade the viewer in on open with the existing `motion::overlay_in(self.is_fullscreen_viewer, …, "viewer-in")` (it replays on every mount, so no generation counter is needed), keep the stage size while loading (show the grid thumbnail or a neutral full-stage canvas), swap thumbnail → full frame without a fade (same picture, sharper; a cross-fade would need two stacked layers), and prefetch the ±1 grid thumbnails.** *Rejected:* a shared-element zoom from the card. GPUI has no layout animation, production cannot read card bounds, and the close could not animate (no exit animations). *Rejected:* a Lumina-only reduced-motion preference. The system setting is already honoured, and a fade is allowed under it (ux_audit §3).
9. **Export and XMP import run as one background task each, with a status-bar line and a final toast. There is no per-item progress or cancel.** The task captures `library_generation`; on completion the toast/banner always shows, but `refresh_after_history` runs only if the generation is unchanged. `ForegroundJobs` is app-level and survives a library switch, so a second export cannot start while the first still writes. A refusal is a toast ("An export is already running"), like the import's. Per-item progress needs a callback in `LuminaEngine::export_items` (a core API change). Follow-up if exports of thousands of items prove slow. *Rejected:* a background job center. That is UX-4-sized, and import, rescan and downloads already have their own surfaces.
10. **"Import into New Library" = pick (or create, since the macOS panel offers New Folder) a destination folder → `open_library` → open the existing import picker once that library's first `ScanComplete` arrives.** Waiting matters: the first-scan root renders no import dialog, and its key handler swallows every key, so a picker answered during a long first scan (the user picked a folder that already holds photos) would open an invisible dialog. A `pending_import_after_open: bool` on `ImportState` carries it; `open_library_inner` clears it (via `abandon_import`) when a different library opens. It reuses `pick_import_folders`/`begin_import` (`app/import.rs:79-160`). *Rejected:* a separate wizard.
11. **Recent libraries: config `recent_libraries: Vec<PathBuf>`, most recent first, deduped by canonical path, capped at 8, added only after a successful open.** Removal is available from the welcome screen (⌫ or the × button), and ⌘K offers "Clear Recent Libraries". *Rejected:* a File → Open Recent submenu. GPUI menus are a static list (`menus.rs`), so it would mean `cx.set_menus` rebuilds plus parameterised actions. ⌘K "Open Recent Library: …" rows (`PaletteTarget::Library(PathBuf)`, beside `Go` and `Year`, not a `CommandId(usize)` in the static command table) are the keyboard path. Existing users are seeded automatically: the startup open of `last_library_path` succeeds and pushes it. Availability (`is_dir`) is checked off the UI thread (an unmounted network volume can block a `stat` for seconds): one `background_executor` task when the welcome screen is first shown or the list changes, and the open path re-checks the one chosen folder.
12. **`pick-folder-btn` → `welcome-open-btn`.** This changes the test contract on purpose: the label becomes "Open Existing Library…". Only `tests/welcome.rs` uses the old name.
13. **Sample library (if the owner approves): generated, not bundled.** About 24 JPEG gradients written with the existing `image` crate into `data_dir()/lumina/Sample Library`, with file mtimes spread over 3 months so the timeline has buckets. There are no license questions and no bundle growth. They carry no EXIF, cameras or places, and the UI says "sample", not "photos".

Independent review against the code at `5110780`. Changes made:

1. **Restore race fix moved to one guard in `apply_restored_session`.** The original fix (cancel in `record_navigation_change`, plus "the `set_search_query` path") missed typed search, which edits `search_query` through `text_input.rs` and never records, and the direct assignments in `tags.rs`. It also needlessly threaded `cx` through 6 call sites. Added tests for typing and card selection, and one that an untouched startup still restores.
2. **Scroll anchor vs. reveal.** GPUI keeps one deferred scroll (`uniform_list.rs:150-168`), so "anchor scroll, then reveal" would have dropped the anchor. The reveal is now conditional. `grid_top_item_id` reads `displayed_rows` instead of `get_active_slice`, which can fall back to SQL. The restore test now uses 200 items so the list can scroll. Also noted that scrolling never triggers a save.
